============================================================
CZĘŚĆ B — PRAWDZIWY PROGRESS
============================================================

Obecny progress jest błędny.

USUŃ jako źródło procentu wszystko,
co bazuje na:

- timerze GUI,
- czasie odtwarzania,
- szybkości dekodowania wejścia,
- samym czasie źródłowym,
- duration × fps,
- przewidywanym czasie,
- callbacku wyprzedzającym faktyczny renderer.

Progress ma pochodzić z rzeczywistych
ukończonych klatek pipeline'u.

============================================================
AUTORYTATYWNY LICZNIK
============================================================

Najpierw znajdź najlepszy istniejący licznik.

Dla AMD preferuj licznik oznaczający,
że klatka faktycznie przeszła production pipeline.

Może to być np.:

processed
encoded
AMF submitted/output
muxed

ale wybierz właściwy na podstawie kodu.

Nie zgaduj.

Progress podczas głównego renderowania:

completed_frames / total_frames.

============================================================
TOTAL FRAMES
============================================================

Ustal rzeczywistą liczbę klatek źródła.

NIE używaj bezwarunkowo:

ceil(duration * fps)

ponieważ dla materiałów takich jak GoPro
może dawać błędny wynik.

Jeżeli projekt posiada wiarygodny
exact frame count:

użyj go.

Jeżeli dokładny total nie jest dostępny:

progress powinien być indeterminate
do czasu uzyskania poprawnego total,

zamiast prezentować fałszywy procent.

============================================================
100 PROCENT
============================================================

Pasek NIE może pokazać 100%,
dopóki eksport faktycznie nie jest zakończony.

Podczas ostatniego flush/drain/mux:

można pozostawić:

99%

i status:

"Finalizacja..."

Dopiero po sukcesie:

100%
"Gotowe"

============================================================
STATYSTYKI

Może być jedna lub dwie linie,
zależnie od istniejącego GUI.

============================================================
FPS
============================================================

FPS ma być REAL throughput:

completed_frames / elapsed_render_time

lub istniejąca poprawna metryka TRUE FPS.

Nie używaj source FPS jako render FPS.

============================================================
ETA
============================================================

ETA:

remaining_frames / measured_render_fps.

Można zastosować lekko wygładzoną średnią,
żeby ETA nie skakało.

Nie komplikuj tego.

Jeżeli FPS nie jest jeszcze wiarygodny:

ETA = "--:--".

============================================================
KRYTYCZNE — BRAK GPU READBACK
============================================================

ABSOLUTNIE NIE RÓB:

final 4K GPU HUD
→ GPU readback
→ CPU
→ Qt.

NIE używaj:

staging texture readback
Map()
CopyResource do staging
forced GPU sync
GetData wait

dla HUD Preview.

Finalny renderer NIE może czekać na preview.

============================================================

============================================================

udostępniać snapshot aktualnego stanu HUD.

GUI lub osobny lekki preview worker
renderuje z tego HUD w małej rozdzielczości.

============================================================

============================================================

Następne preview:
640 lub nowsze.

- speed,

- battery,

============================================================
WIZUALNA ZGODNOŚĆ
============================================================

HUD Preview NIE musi być pixel-identical
z finalnym 4K GPU output.

Ma być wizualnie zgodnym podglądem:

- ten sam layout,
- te same wartości,
- te same pozycje,
- proporcjonalne skalowanie,
- właściwa mapa,
- właściwe wykresy.

Nie próbuj dla preview kopiować
GPU map/chart/gauge textures z produkcji.

============================================================
THREADING
============================================================

Final render worker:

NIGDY nie może czekać na GUI.

Do GUI przesyłaj:

lekki immutable snapshot stanu.

Jeżeli renderowanie preview wymaga CPU:

wykonaj je poza krytyczną pętlą exportera.

Preferowane:

dedykowany lightweight preview worker

lub istniejący bezpieczny mechanizm preview.

QPixmap/QWidget update:
tylko GUI thread.

============================================================
BACKEND CONTRACT
============================================================

Jeżeli trzeba rozszerzyć callback exportera,
utwórz minimalny backend-agnostic contract,
np.:

on_render_progress(
    completed_frames,
    total_frames,
    elapsed,
    fps,
    hud_state
)

HUD state nie musi być wysyłany
w każdym callbacku.

Może być aktualizowany 1 Hz.

Nie przebudowuj encoderów.

AMD jest głównym acceptance backendem.

NVIDIA/Intel:
nie zmieniaj ich pipeline'u.
