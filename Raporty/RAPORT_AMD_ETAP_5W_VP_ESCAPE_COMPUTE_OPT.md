## Phase B — VP-free compute feasibility

VP REFERENCE SEMANTICS:

- input = decoder-owned P010 texture, 3840x2160, array slice selected per frame
- output = persistent NV12 texture, 3840x2160, output pool unchanged at 8
- rotation = native source rotation remains 180 degrees in the canonical path;
  the compute prototype did not claim parity for rotation semantics
- source/destination rect = full input/output rectangles in the reference VP path
- frame format = progressive
- color/range = existing VP setup was preserved; the code reports legacy mode 0
  (`inNominal=0`, `outNominal=0`), while decoder metadata identifies BT.2020 HLG
- other = reference VP also owns the current stream-state and rotation API calls;
  these were intentionally not silently reproduced in the rejected prototype

D3D11 CAPABILITIES:

- P010 SRV = `SUPPORTED` on the real AMD device; `CreateShaderResourceView1`
  returned `S_OK` for the Y plane view
- P010 UV plane SRV = `SUPPORTED`; `S_OK` for the interleaved UV plane view
- NV12 plane UAV = `SUPPORTED` by the existing `ID3D11Device3` output-plane UAVs
- extra copies required = none in the attempted architecture; no CPU conversion
  or GPU readback was introduced

shader. The shader uses 16-bit normalized storage, recovers 10-bit codes, and
uses a diagnostic truncating `>> 2` quantization. No RGB round-trip was used.
